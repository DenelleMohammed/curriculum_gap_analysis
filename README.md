# Curriculum Gap Analysis

Which data science skill areas does the UWI B.Sc. Computer Science (Special) curriculum
**not** cover?

This project answers that question empirically. It scrapes live Data Scientist job
postings, extracts skills from both the postings and the official course syllabi with
[SkillNER](https://github.com/AnasAito/SkillNER), models the job market as a set of LDA
topics, and then tests the curriculum's coverage of each topic against a bootstrapped
baseline built from job postings in completely unrelated professions. Topics the
curriculum covers no better than an unrelated-jobs baseline are reported as **gaps**, and
a Coursera scraper looks up a MOOC for each gap topic.

**Current result:** 7 of 17 data science job topics are classified as gaps.

| Topic | Label | Curriculum score | Baseline P5 |
|------:|-------|-----------------:|------------:|
| 14 | databases embedding, knowledge graph, rest apis | 0.7034 | 0.8867 |
| 6 | economic indicator, requisition, systems thinking | 0.6964 | 0.9984 |
| 0 | refinement, data exploration, business analytics | 0.6886 | 1.1994 |
| 2 | analytical skill, projects collaborate, c | 0.6713 | 1.1498 |
| 12 | business acumen, testing regression, google cloud | 0.6274 | 1.0692 |
| 7 | analysis business, benchmarking, strategies business | 0.5355 | 0.9312 |
| 5 | sprint planning, tested code, requirements manage | 0.4479 | 0.7422 |

## Why an unrelated-jobs baseline?

A raw LDA topic score tells you nothing on its own — every corpus scores something against
every topic, because common words ("management", "communication", "data") leak into all
topics. The question is not *"does the curriculum score above zero on this topic?"* but
*"does it score higher than a body of text that has nothing to do with data science?"*

So the pipeline collects a control corpus of postings for nurses, teachers, accountants,
chefs, pharmacists and similar roles, and scores that corpus against the same data science
topics. A topic where the curriculum scores **below the 5th percentile** of the
bootstrapped control distribution is a genuine gap: on that topic, the syllabi carry no
more signal than a job ad for a restaurant manager.

## Methodology

### 1. Data collection

**Job postings.** `reeduk_scraper.py` and `workopolis_scraper.py` drive headless Chrome
over reed.co.uk (UK) and workopolis.com (Canada). Each scraper collects two groups from
the same source, so the treatment and control corpora share their formatting quirks and
page boilerplate:

- `data_science` — the search term `Data Scientist`
- `unrelated` — ten non-technical roles (Registered Nurse, Primary School Teacher,
  Accountant, HR Officer, Sales Representative, Restaurant Manager, Chef, Warehouse
  Supervisor, Construction Supervisor, Pharmacist), capped by `CATEGORY_TARGETS` so the
  control group stays comparable in size to the data science group.

Both write a single JSON array of records carrying `url`, `title`, `company`, `location`,
`description`, `source` and `category`. `linkedin_scraper.py` is included and works, but
LinkedIn's anti-bot measures made the yield unreliable, so its output is **not** wired into
`preprocess_jobs.py` — the current results use Reed and Workopolis only.

**Course catalogue.** `data/raw/outcomes_and_content.json` holds the 44 COMP/INFO course
syllabi (`description`, `rationale`, `aims`, `learning_outcomes`, `course_content`,
`thematic_areas`). This file is compiled from the published UWI DCIT course documents
rather than scraped, and is the one raw input the pipeline does not regenerate.

### 2. Preprocessing

`preprocess_jobs.py` and `preprocess_courses.py` apply the *same* cleaning rules to both
corpora, which matters because the gap analysis later matches skills as exact string
tokens:

1. Strip HTML tags.
2. Truncate source-specific page chrome (Reed's "Browse jobs by locations", Workopolis's
   "Our most similar jobs") that the scrapers swept in with the description.
3. Repair letter-spaced text (`c o d e` → `code`).
4. Normalise tech variants to canonical SkillNER surface forms — `c + +` → `C++`,
   `dot net` → `.NET`, `amazon web services` → `AWS`, `postgre sql` → `PostgreSQL`, and
   ~35 more.
5. Drop characters outside `[a-zA-Z0-9 + # . / - _]`, collapse whitespace.
6. Tokenise with spaCy `en_core_web_sm`, removing stopwords, punctuation and single
   characters.

Jobs are then filtered to the target role (`data scientist`) plus the unrelated control
roles, deduplicated by URL and again by MD5 hash of the cleaned text, tagged with a region
(from the source domain) and a category (`AI` / `Unrelated`), and split into three files:
all jobs, data science jobs, unrelated jobs.

Courses get the same treatment over the concatenation of description, rationale, aims,
learning outcomes and course content, with MD5 deduplication.

### 3. Skill extraction

Both extractors run SkillNER (`SKILL_DB` + spaCy `PhraseMatcher`) over the cleaned text and
keep matches — full matches and scored n-grams — above a confidence of 0.7. The raw output
is noisy, so each match passes through:

- **`skill_normalisation.py`** (shared by both extractors, and the reason they exist as one
  module): American → British spelling (`visualization` → `visualisation`), singularisation
  of the head word (`code reviews` → `code review`) with a protected-plurals list so
  `statistics`, `pandas`, `aws` and `kubernetes` survive intact, and junk removal. Before
  this module the two corpora drifted — job ads said "data modeling", syllabi said "data
  modelling", and the curriculum got no credit for a skill it teaches.
- **Local filters**: generic verbs and phrases (`build`, `manage`, `data science`,
  `analytics`, `problem solving`), boilerplate (`job description`), phrases longer than
  three words, and n-gram artefacts where a word repeats inside one phrase
  (`data science data`) — a sliding-window collision, never a real skill.

`job_skill_extractor.py` then runs a second pass per file, dropping any skill occurring
fewer than `MIN_FREQ = 2` times. The filter is scoped to each file's own population, so the
much larger unrelated corpus can't dilute or inflate the data science threshold.

`course_skill_extractor.py` additionally splits its output by thematic area (COMP →
computer science, INFO → information technology) and filters to the explicit B.Sc. Computer
Science (Special) course list — core plus electives — in `CS_SPECIAL_COURSE_CODES`. That
subset, 37 courses, is what the gap analysis treats as "the curriculum".

### 4. Choosing the number of topics — `coherence-score.ipynb`

Multi-word skills are joined with underscores (`machine_learning`) so LDA treats them as
single tokens, and the thematic-area tags `computer_science` / `information_technology` are
dropped so they don't dominate. The notebook then sweeps 1–19 topics, fitting an
`LdaModel` (`passes=10`, `iterations=100`, `random_state=42`) at each `k` and scoring it
with gensim's `c_v` coherence, for both the CS course corpus and the data science job
corpus. `DS_NUM_TOPICS` in the gap analysis is set from this sweep (currently **17**).

### 5. Gap analysis — `gap-analysis.ipynb`

1. **Fit the market model.** Train LDA with `DS_NUM_TOPICS` on the data science job corpus
   (74 postings). This defines the topic space; the curriculum is never used to fit it.
2. **Label the topics by distinctiveness, not probability.** Ranking a topic's words by raw
   probability just surfaces `python`, `sql`, `machine_learning` for every topic. Instead
   each word is scored by lift — P(word | topic) ÷ P(word | corpus) — over words above
   `MIN_LABEL_PROB = 0.005`, and the top three become the label. That is why the gap labels
   read "sprint planning, tested code, requirements manage" rather than "python, sql".
3. **Score the curriculum.** Collapse all 37 CS Special courses into one bag of skill
   tokens and score it against every topic as Σ count(word) × P(word | topic).
4. **Bootstrap the baseline.** Resample 96 documents with replacement from the 97 unrelated
   postings, collapse to a bag, score it the same way — 1000 times (`random_state`/seed 42
   throughout). This yields a sampling distribution of "what does a non-technical corpus of
   this size score on this topic?"
5. **Classify.** A topic is a gap when the curriculum's score falls below the **5th
   percentile** of that topic's bootstrapped baseline distribution.
6. **Plot.** A horizontal bar chart of curriculum score per topic with the P5 threshold
   marked, gaps in red.

### 6. MOOC recommendation

`coursera_scraper.py` holds the seven gap topic labels in `GAP_TOPICS`, searches Coursera
for each one, and records the top-ranked course title and URL to
`data/mooc/coursera_gap_courses.{jsonl,csv}` — a concrete remediation suggestion per gap.
**This list is hardcoded**: if you re-run the pipeline on fresh data and the gap set
changes, update `GAP_TOPICS` before running the scraper.

## Reproducing the pipeline

### Setup

Python 3.9 and a Chrome install matching the ChromeDriver on your `PATH`
([chrome-for-testing](https://googlechromelabs.github.io/chrome-for-testing/)).

```bash
git clone https://github.com/DenelleMohammed/curriculum_gap_analysis.git
cd curriculum_gap_analysis

python3.9 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt    # includes the en_core_web_sm spaCy model
```

On its first run SkillNER downloads `skill_db_relax_20.json` (~7 MB) and `token_dist.json`
into the working directory. Both are gitignored; leave them at the repo root and later runs
reuse them.

Run every script **from the repository root** — all paths are relative to it.

### Step 1 — Collect job postings *(optional)*

```bash
python scraper/reeduk_scraper.py        # -> data/raw/reed_jobs.json      (121 records)
python scraper/workopolis_scraper.py    # -> data/raw/workopolis_jobs.json ( 60 records)
```

Both scrapers are slow by design (randomised 4–9 s delays) and log to `logs/`. Workopolis
runs non-headless by default so you can watch for CAPTCHAs; Reed runs headless with a
throwaway Chrome profile per run. Because they hit live sites, expect the record counts and
the downstream numbers to differ from the ones quoted here. **Skip this step to reproduce
the published results** — use the `data/raw/` files as-is.

`data/raw/outcomes_and_content.json` is required and is not produced by any script.

### Step 2 — Preprocess

```bash
python preprocessing/preprocess_jobs.py
python preprocessing/preprocess_courses.py
```

Produces:

| File | Records |
|---|---:|
| `data/processed/all_jobs_preprocessed.jsonl` | 171 |
| `data/processed/data_science_jobs_preprocessed.jsonl` | 75 |
| `data/processed/unrelated_jobs_preprocessed.jsonl` | 96 |
| `data/processed/all_courses_preprocessed.jsonl` | 43 |

### Step 3 — Extract skills

```bash
python skill-extractor/job_skill_extractor.py
python skill-extractor/course_skill_extractor.py
```

Both print a per-file summary (records processed, extraction failures, unique skills kept,
top 20 skills) and produce:

| File | Records | Contents |
|---|---:|---|
| `data/skills/all_jobs_skills.jsonl` | 171 | every posting |
| `data/skills/data_science_jobs_skills.jsonl` | 75 | Data Scientist postings |
| `data/skills/unrelated_jobs_skills.jsonl` | 96 | control postings |
| `data/skills/all_courses_skills.jsonl` | 43 | every course |
| `data/skills/cs_courses_skills.jsonl` | 25 | COMP courses |
| `data/skills/it_courses_skills.jsonl` | 18 | INFO courses |
| `data/skills/cs_special_course_skills.jsonl` | 37 | **B.Sc. CS (Special) — used by the analysis** |

This is the slow step: SkillNER annotates each document individually, so budget several
minutes.

### Step 4 — Choose the number of topics

```bash
jupyter notebook notebooks/coherence-score.ipynb
```

Run all cells. Read the optimal `k` off the data science coherence curve and set
`DS_NUM_TOPICS` in `gap-analysis.ipynb` to match. (Notebook paths are relative to
`notebooks/`, so launch Jupyter from there or from the repo root — either works.)

### Step 5 — Run the gap analysis

```bash
jupyter notebook notebooks/gap-analysis.ipynb
```

Run all cells. The notebook prints the 17 labelled job topics, the bootstrap summary, the
gap table, and the curriculum-vs-baseline chart.

Documents entering the model: 37 CS courses, 74 data science jobs, 97 unrelated jobs (the
counts differ by one from the skills files because empty skill lists are dropped in
`prepare_texts`).

### Step 6 — Look up MOOCs for the gaps

```bash
python scraper/coursera_scraper.py      # -> data/mooc/coursera_gap_courses.{jsonl,csv}
```

Update `GAP_TOPICS` first if your gap set differs from the seven above.

## Tuning knobs

| Parameter | Location | Default | Effect |
|---|---|---|---|
| `CATEGORY_TARGETS` | both job scrapers | 70 (Reed), 30 (Workopolis) | size of the control corpus |
| `MIN_FREQ` | `job_skill_extractor.py` | 2 | drops skills seen once in a corpus |
| `NGRAM_SCORE_THRESHOLD` | `course_skill_extractor.py` | 0.55 | SkillNER n-gram confidence floor |
| `CS_SPECIAL_COURSE_CODES` | `course_skill_extractor.py` | 43 codes | which courses count as "the curriculum" |
| `DS_NUM_TOPICS` | `gap-analysis.ipynb` | 17 | LDA topic count for the job corpus |
| `BOOTSTRAP_ITERS` | `gap-analysis.ipynb` | 1000 | bootstrap resamples |
| `RESAMPLE_DOCS` | `gap-analysis.ipynb` | 96 | documents per resample |
| `GAP_PERCENTILE` | `gap-analysis.ipynb` | 5 | strictness of the gap threshold |
| `MIN_LABEL_PROB` | `gap-analysis.ipynb` | 0.005 | lift-based labelling cutoff |

## Limitations

- **Corpus size.** 74 data science postings and 37 courses is small for LDA; topics are
  interpretable but not stable across reseeds. `random_state=42` is fixed throughout so
  runs are repeatable, not so they are robust.
- **Two job markets, one curriculum.** Postings come from the UK and Canada; the curriculum
  is Trinidadian. The gap is measured against an international market by construction.
- **Exact-string matching.** Coverage is credited only when a curriculum skill token
  matches a job skill token exactly. `skill_normalisation.py` closes the obvious
  morphological gaps, but genuine synonyms still miss.
- **Syllabi under-describe teaching.** Course documents state intended outcomes, not what is
  actually delivered; a skill taught but not written down is invisible to this pipeline.
- **Scraper fragility.** The Coursera, Reed and Workopolis selectors are pinned to markup as
  of the last run and will need updating when those sites change.
